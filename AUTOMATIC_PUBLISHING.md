# Bharat Itihasa — one-time automatic publishing setup

After setup, Admin changes are published from the website itself. You will not need to manually edit or upload `overrides.js` to GitHub for routine content updates. The secure backend commits updates to `vjcore/Indian_history`, then GitHub Pages deploys the updated site for all devices.

**One-time setup still requires access to GitHub and Cloudflare:** GitHub Pages is static hosting and cannot securely write to its repository using browser-only code. This project uses a Cloudflare Worker as the authenticated bridge. The GitHub token stays in Cloudflare secrets, never in public JavaScript.

## A. Upload the project once

1. Download and extract the complete ZIP.
2. Upload the extracted project files and folders into the root of `https://github.com/vjcore/Indian_history`, replacing the corresponding old files.
3. Make sure GitHub Pages deploys from branch `main` and folder `/(root)`.
4. Keep `index.html`, `data/`, `js/`, `css/`, `images/`, and `worker/` in the provided structure.

## B. Create a fine-grained GitHub token

1. Open https://github.com/settings/personal-access-tokens/new.
2. Give the token a name such as `Bharat-Itihasa-Publisher`.
3. Resource owner: `vjcore`.
4. Repository access: **Only select repositories** → `Indian_history`.
5. Repository permissions: **Contents — Read and write**. Leave other permissions at their minimum/default values.
6. Generate the token and copy it temporarily. Do not add it to a source file or paste it into chat.

## C. Deploy the Cloudflare Worker

1. Sign in at https://dash.cloudflare.com/.
2. Open **Workers & Pages → Create → Create Worker**. Name it `bharat-itihasa-publisher`, then deploy it.
3. Open the new Worker and choose **Edit code**.
4. Replace the starter code with all contents of `worker/src/index.js` from this project. Save and deploy.
5. In Worker **Settings → Variables and Secrets**, configure these ordinary variables:

   | Variable | Value |
   |---|---|
   | `GH_OWNER` | `vjcore` |
   | `GH_REPO` | `Indian_history` |
   | `GH_BRANCH` | `main` |
   | `SITE_ORIGIN` | `https://vjcore.github.io` |

6. Add these three as **Secrets** (not plain-text variables):

   | Secret | Value |
   |---|---|
   | `GH_TOKEN` | The fine-grained GitHub token created in section B |
   | `ADMIN_PASSWORD` | A strong, unique password used to sign in to Admin |
   | `SESSION_SECRET` | A long random secret of at least 32 characters, preferably generated by a password manager |

7. Save/deploy the Worker again. Copy the Worker URL Cloudflare shows, such as `https://bharat-itihasa-publisher.YOUR-SUBDOMAIN.workers.dev`.
8. Open `https://YOUR-WORKER-URL/api/health`. It should return JSON showing `"ready":true` when all three secrets exist.

`SITE_ORIGIN` must match the page's origin exactly, with no path or trailing slash. For this GitHub Pages project site, the origin is `https://vjcore.github.io` even though the page URL contains `/Indian_history/`.

## D. Connect Admin from the website

1. Open https://vjcore.github.io/Indian_history/.
2. Choose **Menu → Admin**.
3. In the sign-in form, paste the Worker URL and enter the `ADMIN_PASSWORD` secret you configured in Cloudflare.
4. Sign in. The Admin dashboard should show **Automatic GitHub publishing**.
5. Click **Publish current changes now** once to test the connection.
6. Once the first successful publish completes, the Worker automatically commits the non-secret URL into `data/publish-config.js`. After GitHub Pages deploys that commit, every device can discover the Worker URL from the site. You do not need to configure it separately on each device.

## E. Use the website only for routine changes

From Admin, create/edit a topic, edit structured headings, change the home page, restore/delete a topic or import a backup. The save action sends the current settings through the authenticated Worker and commits `data/overrides.js` to GitHub automatically. Each device must sign in to Admin with the backend password, but it does not need to upload files or make a GitHub commit manually.

A successful publish does not mean the public page changes instantly; GitHub Pages needs time to deploy. Admin shows an error if the backend or GitHub commit fails. Do not assume a locally saved change is global unless publishing succeeds.

## Troubleshooting

- **Worker returns `ready:false`:** configure `GH_TOKEN`, `ADMIN_PASSWORD`, and `SESSION_SECRET` under Worker Secrets and deploy again.
- **401 when saving:** sign out and sign in again; Worker sessions expire after eight hours.
- **403 from GitHub:** verify that the fine-grained token belongs to `vjcore`, is scoped to `Indian_history`, and has Contents read/write permission.
- **Origin blocked:** `SITE_ORIGIN` must be exactly `https://vjcore.github.io`.
- **Save is local only:** confirm you signed in through the Worker URL and the Admin panel shows a connected publishing session. Use **Publish current changes now** to see the specific failure.
- **One device shows stale edits:** refresh after GitHub Pages finishes deploying. The published version stamp clears older local browser draft caches after the newer publication is loaded.
- **Large image fails:** use repository-relative image paths such as `images/topics/ashoka.jpg`; many embedded data URLs can exceed browser or Worker size limits.

## Security notes

- Never put the GitHub token in `data/publish-config.js`, `data/overrides.js`, HTML, CSS, or browser JavaScript.
- `data/publish-config.js` contains only the public Cloudflare Worker URL. The Worker creates/updates it during the first successful publish.
- `ADMIN_PASSWORD` and `SESSION_SECRET` remain Cloudflare secrets. The old browser-only password is disabled in this package.
- A GitHub token can write to this repository. Keep it scoped only to `Indian_history`, rotate it if exposed, and revoke it if no longer needed.
