# Bharat Itihasa — Indian History website

This complete project is designed for GitHub Pages. It preserves the existing dark chocolate and parchment home-page design, all history sections, topic data, images and Admin features.

## Admin edits that update every device

This project includes automatic GitHub publishing. After the one-time setup in [`AUTOMATIC_PUBLISHING.md`](AUTOMATIC_PUBLISHING.md), open the website, choose **Menu → Admin**, sign in through the Cloudflare Worker, then edit and save topics or home-page settings directly on the website. Saves commit `data/overrides.js` to GitHub; GitHub Pages deploys the changes for all visitors. You do not need to manually edit or upload files to GitHub for routine content changes.

Initial setup does require uploading this project to your GitHub repository once and configuring a secure Cloudflare Worker secret. Your GitHub token must never be placed in this repository or browser JavaScript. The Worker URL is public, and the Worker writes that URL to `data/publish-config.js` automatically during the first successful publish so other devices can discover it without per-device setup.

## Project folders

- `index.html` — page shell and script includes
- `css/style.css` — site theme and responsive layout
- `js/app.js` — routing, home page, timeline, topic details, Admin and publishing integration
- `data/data.js` — base historical topic catalogue
- `data/extra.js`, `data/modern.js` — supplemental historical content
- `data/books.js`, `data/books_facts.js` — religious-book topic information
- `data/overrides.js` — generated by the Admin publishing backend; do not manually edit once automatic publishing is active
- `data/publish-config.js` — public Worker URL; no secrets belong in this file
- `worker/src/index.js` — authenticated Cloudflare Worker that commits Admin data to GitHub
- `worker/wrangler.toml` — Worker project configuration
- `AUTOMATIC_PUBLISHING.md` — initial setup and troubleshooting guide

## Admin capabilities

The Admin panel can search and edit existing topics; add new topics; create structured explanations and custom heading/content blocks; configure per-topic “More information” links, images and galleries; edit home title, subtitle, background and creator information; hide topics; move topics to Trash; restore them; permanently delete topics; import/export backups; and publish current changes directly to GitHub.

## Images

For reliable publication, put images into the repository (for example `images/topics/ashoka.jpg`) and use the relative path in Admin. Very large embedded browser-uploaded data URLs may exceed request or browser storage limits.

## Deployment behaviour

A successful publish updates the repository. GitHub Pages needs a short time to finish deployment, so a newly saved change may not appear instantly. A newer published version stamp helps the website discard stale local draft caches on devices that were used for earlier browser-only editing. If a save reports a publishing error, it is not globally published yet; reconnect and retry from Admin.

## Security

- Never commit `GH_TOKEN`, `ADMIN_PASSWORD`, or `SESSION_SECRET` to GitHub.
- `GH_TOKEN`, `ADMIN_PASSWORD`, and `SESSION_SECRET` belong only in Cloudflare Worker Secrets.
- The backend token is scoped to this repository and is never sent to the browser.
- The Admin session expires after eight hours; sign in again when prompted.
